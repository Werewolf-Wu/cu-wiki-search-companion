## 升版前门禁

### 行为回归

- [x] RC 同轮页面发生 `info -> revisions` 新 revision 竞态时，正常候选与游标仍原子提交，错配正文不落库，竞态页留下可恢复 pending job。
- [x] RC 明确返回 missing 时不创建或复活页面；更旧/畸形正文响应仍使整轮失败且不推进游标。
- [x] 正文搜索先完成排序与截断，只为最终 `limit` 条结果生成摘要；title boost 与稳定排序不变。
- [x] NFKC、繁简、大小写与空白变化不会令摘要漂移为空或只剩省略号。
- [x] 缺失或损坏的 syncState 不进入字符串拼接、NaN 或回退序列循环；关键游标损坏停止写入并可诊断。
- [x] 缺 `local-sequence` 时，读取、刷新、检查和发布使用同一恢复值，防抖发布最终收敛。
- [x] Wiki API 只重试瞬时失败、`maxlag` 与 `ratelimited`；永久性 4xx 立即失败。
- [x] Lua 比较表达式不再成为返回键；Wikitext 实体只解码一层。
- [x] AltGr/Ctrl+Alt 不触发 Alt+K；面板内任意控件聚焦时 Escape 均可关闭，IME 组合期间除外。
- [x] 重叠 Data 规则保存各自执行并获得自己的结果；文件锁不可用与异步失败具有准确、可观察的错误。

### 一致性与性能

- [x] facts、jobs、localSeq、RC/对账游标原子性与 transaction callback 后 abort 回归保持通过。
- [x] content jobs 准备、进度与对账收尾在 500/2,000/10,000 条合成数据上保持线性操作量，不全量重写未变化 jobs。
- [x] 维护诊断和队列修复不同时保留全部正文 payload；文件批次不反复重读完整文件表。
- [x] 快照发布只做一次 UTF-8 编码；有效快照恢复只做一次完整 payload parse，紧随其后的 inspect 不重复解析。
- [x] title/content/lua 的同步重建、异步重建、快照恢复与 tombstone 增量结果签名一致。
- [x] 二字 CJK 不启用编辑距离 fuzzy；既有标题 exact/prefix/substring/繁简召回不退化。

## 升版与发布候选门禁

升版前门禁全部通过后：

1. 将 package、lockfile 与 userscript metadata 从 `0.3.0` 提升到 `0.3.1`。
2. 再跑全量测试、生产构建、metadata、许可证、build marker 与激活规则检查。
3. 补充下方证据，并一次性更新 `HANDOFF.md`；普通账号端到端仍未完成时必须明确保留该边界。
4. 生成 `release: prepare verified 0.3.1` 本地提交并快进本地 `main`。
5. 停止；不 push、不创建 tag、不触发 Nightly。
